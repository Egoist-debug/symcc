## 存放方式

- `tasks/` 保存本次任务的 PRD、设计、实施计划、上下文清单、研究及检查报告。
- `spec/` 保存该任务引用的规范快照，不包含其他任务、个人日志、会话运行时或凭据。
- 本仓库保存暂停时的完整任务检查点；原工作区
  `.trellis/tasks/10-30-symcc-paper-completion` 保留真实工作目录。
  Trellis 拒绝指向任务根目录之外的符号链接，因此不绕过其边界校验。
- 这里不是另一套 Trellis 安装，不创建子仓库 `.trellis/` 来覆盖父工作区的运行时。
  Trellis 脚本与会话管理仍在原工作区。

上下文 JSONL 的 `file` 以包含 `symcc/` 的工作区根为基准，引用的规范和本任务
研究文件均已放入本仓库。独立阅读此仓库时，将路径开头的 `symcc/` 视为仓库根。
研究中保留的绝对路径、历史批次和 `/tmp` 日志路径是当时证据位置，不保证随 clone 存在。

## 恢复顺序

仅在用户要求恢复后，先核对工作区与本仓库检查点，避免覆盖任何一侧后续修改，
再取消 `task.json` 的 `meta.paused` 标记并激活原任务；
先完成暂停清单中的三组生成对照迁移、审计边界和消费链联动，再执行第二批独立检查。
下次提交时同步任务检查点，不把本次快照误认成自动双向同步目录。
不要将小目标 solver/AFL 验证当作真实 DNS 链路或正式实验完成。
