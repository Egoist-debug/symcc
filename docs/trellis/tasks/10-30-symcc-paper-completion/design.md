# 技术设计：论文证据闭环的最小补全

> 当前为待批准方案；不表示下面的修复和实验已经执行。论文范围见 [paper-plan.md](paper-plan.md)，当前代码事实见 `research/` 专项报告。

## 1. 边界与复用

保留现有 C++17/xmake、`gen_input`、AFL custom mutator、SymCC helper、resolver patch 和 `tools/dns_diff` 的职责。**不为论文重新造编排器，不把已有 Python 工具整体迁移到 C++，不增加新的数据库或服务。**

首批具体范围是现存的缓存语义比较、Unbound 注入保真和 acceptance oracle 三项缺口，见 `implement.md` 的 A1–A3。旧符号文件断点、QNAME 指针等原始案例已有代码修正，先保留验证边界，不重复重写。

既有数据流：

`冻结初始语料 → producer/变异与局部符号生成 → 原始 DST1 队列 → 同源 replay → oracle/cache 比较 → triage → 聚合/审计 → 论文图表`

修复必须覆盖受影响的整个链路，但只改真实根因及其调用方、测试、配置和契约。研究报告里的历史问题不自动转化为待改代码。

## 2. 输入和 adapter 的语义边界

- 原始 transcript 和内容哈希不可变；各 adapter 接收同一逻辑事务。
- 只允许按实际连接映射调整必要的传输绑定信息。DNS flags、计数、RR 内容及状态相关字段不能为“让目标跑通”而被静默修改。
- 确需转换时保留原始输入、转换后的输入及理由；论文只比较在声明的语义等价范围内的样本。
- 不支持某种输入、cache 观测或 post-check 的目标必须明确报告能力边界，不能补默认成功值。
- QNAME 长度、RR 移植和压缩指针处理须保持引用有效；无法安全变异时拒绝该操作并记录原因，不把结构损坏误当成目标行为。

## 3. oracle 与缓存比较

- 把“目标进程运行”“协议解析”“上游响应被接纳”“缓存状态改变”“后续查询使用该状态”分开。
- 本地 `SERVFAIL`/拒绝、超时、残留状态、非缓存直接回答都不能仅凭存在响应就计作接纳或缓存命中。
- 比较对象是语义 RRset 与相关状态，不是 resolver 名称、绝对路径或 dump 文本布局。
- 共同缓存比较保留 before/after 语义 delta 定义，前提是两端 before 的共同投影等价。初态不同则保守不可比较；不把相对变化偷换成任意终态差异。缺失快照继续是 unknown，不能由失败补缺路径构造为空缓存。
- 名称大小写、顺序、展示格式等可按协议语义归一化；TTL、信任等级、负缓存等可能有研究意义的字段不能无条件删掉。易漂移字段的处理必须用正反例确定。
- 必须有“身份不同但语义相同不报差异”和“关键字段确实不同仍报差异”的成对回归。
- 缺陷确认依赖受控上游、前后状态、后续查询和规范/配置解释；majority vote 不能自动当作真值。

## 4. 符号生成与执行来源

- 先定位真实符号输入从读取、DNS 解析、分支约束到输出候选的路径；普通文件 I/O 不能被默认视为保留符号依赖。
- 最小链路验证必须观察到输入字节影响目标分支，生成候选能在具体执行中改变路径，并有实际队列回流。
- 分开记录 producer 运行和 queue replay；`campaign-close` 的重放次数不能冒充 producer 的独立重复次数。
- seed、命令、配置、时间区间、退出状态和输出须取自实际执行。缺失来源的历史批次保留缺失，不追补成虚构的已执行记录。
- 第二批保留显式 `PRODUCER_RANDOM_SEED`，仅缺省时生成；`execution_mode` 显式区分实际生成和共享队列重放，缺失/未知模式不能默认视为生成。
- 初始语料摘要、内容队列摘要和执行身份各自表达不同事实；内容去重不能混入 run 时间戳后再宣称语料独立。
- 排除 `*.meta.json` 的队列摘要标识为 `sha256-relative-path-size-content-v2`；旧 v1 可读但不能自动获得新来源资格，不改写历史摘要。
- 独立运行允许碰巧相同的输出，故不能用“hash 必须不同”替代进程与来源证据。
- 第二批已核验 `no_cache_delta` 与 `full_stack` 的生成命令/反馈参数等价；新默认生成组收敛为 `full_stack / afl_only / no_mutator`，旧第四标签仅分析兼容，不计作额外生成机制。

## 5. 结果契约与兼容

复用 `docs/DNSPoisonEvidenceContract.md`，以 `tools/dns_diff/schema.py` 为语义 owner；实现前核对 C++ 等消费端的镜像契约。

- 保持 `analysis_state = included | excluded | unknown`，缺失不能默认为 `included`。
- 不把 unknown、未运行、无统计支持转换为零；单 run 不生成虚假的样本标准差或置信区间。
- 正式 `afl_only` 基线与矩阵内部基线继续分开，比较键必须完整。
- 如确需新增来源/状态字段，采用最小增量契约，联动所有实际消费者和回归，不借机大改 schema。
- 旧 artifact 保持可读取，但旧语义不能自动获得新的可信等级；原始产物只读，新汇总写新目录并标记重分析版本。
- publication audit 负责既有结构/来源检查；它只是论文证据的必要条件，不证明算法新颖性、因果正确性或漏洞成立。

## 6. 实验隔离和资源

- 仅在本地受控 DNS 测试区和 resolver 环境运行；不能误连公共基础设施。
- 每个 run 独立工作目录、端口和状态清理；失败/超时也须回收进程，不能污染下一个 run。
- 保留 lock 与补丁链路，不直接编辑被忽略的 subject 目录作为最终修复。
- 先确认原生二进制对应当前源码和配置，再跑有限测试；不能直接引用旧 build 的成功作为本轮验证。
- G1 pilot 的边界见 `paper-plan.md`；正式实验的 CPU/内存/磁盘和并发额度另行确认。

## 7. 回滚与生效范围

- 代码按独立可验收批次提交供用户审阅；不自动推送。
- 每批只改根因相关代码、测试与必要的契约/文档，不删除历史数据。
- 一旦改变 oracle、cache 等价规则、输入语义或 producer 来源，相关历史发现/主表必须重新验证；不能仅重画旧图。
- 如果端到端 pilot 不通过，停止正式矩阵扩展，把阻塞定位到输入、adapter、符号链路、来源或分析环节。

## 8. 备选方案与取舍

| 选择 | 推荐 | 理由 |
| --- | --- | --- |
| 先扩 resolver 还是先验证语义 | 先验证 BIND9/Unbound 的可控正负例 | 错误测量扩到更多目标只会扩大噪声 |
| 先做完整 hybrid 长跑还是验证符号路径 | 先最小分支与回流证据 | 避免把配置文件里的开关当成真实执行 |
| 复写全部旧结果还是新批次 | 保留旧批次、新建运行与重分析目录 | 避免污染可追溯记录 |
| 先换架构还是原模块修根因 | 原模块内最小修复 | 新架构本身不解决论文有效性 |
| 不足的统计填零还是保留缺失 | 保留缺失、明确原因和样本数 | 零是观测值，不是“没测到”的表示 |
