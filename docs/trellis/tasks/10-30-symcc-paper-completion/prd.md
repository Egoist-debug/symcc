# SymCC 论文规划与代码实验补全

## 目标

核验 DNS 差分混合测试的论文贡献与证据，规划最小代码修复、可复现实验及投稿材料。

## 已确认事实

- 用户希望根据 `symcc/` 的工作规划发表论文，并补全必要代码与实验。
- 用户于 2026-10-30 同意创建任务并进入规划，并在审阅最终方案后以“行，开始”批准首批 A1–A3 实现。
- 已有 `.trellis/tasks/08-17-review-symcc-experiments/` 的只读审查资料，记录了语义判定、符号传播、producer 独立性及结果统计风险。历史发现须对当前代码重新核验，不能直接视为仍然存在。
- 当前授权覆盖首批代码修复、对应测试和有限本地验证；不覆盖第二批 producer 改造、历史结果覆盖或长预算实验。
- 本轮基线为 `symcc/` 的 `paper` 分支，提交 `f08a6c8935c9d25ff0319fdc8b6723d49648322a`；研究开始时工作树干净。
- 当前代码已修正多个旧问题，但仍核验出三类语义缺口：缓存变化与跨端差异混淆、Unbound 单端修复注入内容、acceptance 校验不足且跨端不一致，详见 `research/code-gaps.md`。
- 实验资料中存在真实约一小时的 BIND9 producer，但所查四变体矩阵主要是共享队列 replay，不能支持独立 hybrid 消融；指定 RQ2 批次仍失败，历史摘要规则与当前代码存在差异，详见 `research/experiment-gaps.md`。
- ResolverFuzz、ResolFuzz、BGF-DR 已覆盖许多现有方法组合；论文不能以组合本身或 C++ 重写声称原创，详见 `research/related-work.md`。

## 需求

- R1：区分 SymCC 等已有工作的能力和本项目新增贡献，以一手文献与代码证据约束创新性表述。
- R2：给出论文主线、章节安排、研究问题和逐项证据要求。
- R3：按对结论有效性的影响排列代码缺口，识别调用方、测试、配置及结果契约的影响范围。
- R4：规划公平对照、独立重复、消融、语义判定、统计分析、失败记录和可复现材料。
- R5：在最终方案获批后分阶段实施；小规模验证通过之前不展开完整实验矩阵。

## 验收标准

- [x] R1：每项拟议贡献有对应实现位置、最接近的已有工作及尚未证明的边界。
- [x] R2：论文规划覆盖引言、背景与相关工作、方法、实现、评估、局限和结论，不编造性能或漏洞发现。
- [x] R3：形成可独立验证的最小修复批次与回归标准，区分已核验缺陷、历史问题和待验证假设。
- [x] R4：实验设计明确输入、版本、预算、重复单位、统计口径和失败/缺失值处理规则。
- [x] R5：复杂任务具备 `prd.md`、`design.md`、`implement.md` 及真实上下文清单；用户已批准最新方案和首批范围。

## 推荐首批交付

- 先修缓存共同语义、Unbound 注入保真和跨 resolver acceptance 三项已核验问题，并补端到端调用结果的正反例。
- 本批不改写通用 SymCC runtime，不扩展 resolver，不运行正式或后台 fuzzing。
- 后续再补实际 producer/符号回流证据、种子与统计契约，通过受控 pilot 后另行批准完整实验。
- 首批验收不要求“发现新漏洞”或“性能提升”；要求测量结果不被已知 harness/统计伪象污染。

## 范围外

- 不把工程审计的 `ready`、运行成功或差分告警直接当成科学有效性、漏洞或可发表性证据。
- 不重写通用 SymCC 编译器或开展与核心论文论点无关的扩展。
- 不访问公共 DNS 目标进行攻击实验，不自动提交论文、发布漏洞或推送代码。
- 不默认批准小时级/多日级实验的资源占用。

## 审批与后续决策

- 论文主线与首批范围的推荐方案已写入 `paper-plan.md`、`design.md`、`implement.md`，没有尚待用户提供才能开展首批修复的技术信息。
- 首批实现已获批准；按 `implement.md` 的 A1–A3 顺序实施，后续阶段不因本次批准而自动启动。
- 首批提交并推送后，用户再次要求继续任务，第二批代码与有限验证现已启动；这不自动批准正式实验预算。
- 目标 venue、正式预算、人工标注安排在正式实验阶段前再确认；未预设用户同意小时级或多日级运行。
