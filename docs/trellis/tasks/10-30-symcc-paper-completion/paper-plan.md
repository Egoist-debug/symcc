# SymCC 衍生论文规划

> 规划版本：2026-10-30。当前是研究与实施提案，不是已完成实验的论文。代码基线及调研边界见 [research/baseline.md](research/baseline.md)。

## 结论与主线

推荐暂定题目：**面向 DNS 缓存状态语义的事务级差分测试与缺陷验证**。

沿用仓库已有的 BIND9 单一 producer、DST1 transcript 和多 resolver replay 路线，回答：**怎样产生可比较的 DNS 交互，并把实现差异转化为可验证的状态语义缺陷候选？**

- SymCC 是使用的混合测试技术，不直接充当本项目原创贡献。
- “支持六个 resolver”“有证据 bundle”“审计 ready”是实现/复现能力，不单独构成研究创新。
- 在符号路径端到端闭环和独立消融成立之前，不把“符号执行显著提升发现能力”写进题目或摘要。
- [INFERENCE] 这一主线比先承诺 hybrid 性能提升更符合已有工程基础；是否足以发表，取决于与最接近工作相比的实质差异及正式结果。
- 核心边界：差异不等于缺陷，缓存命中不等于投毒，运行完成不等于结论有效。

### 已核验的最近邻与定位修正

- [ResolverFuzz，USENIX Security 2024](https://www.usenix.org/conference/usenixsecurity24/presentation/zhang-qifan) 已覆盖 query-response fuzzing、跨实现缓存比较和聚类。
- [ResolFuzz，ESORICS 2023](https://bushart.org/publications/2023-esorics/resolfuzz.pdf) 已覆盖统一逻辑输入、多条权威响应、缓存后检、重复重放、启发式和指纹；其论文集出版年份为 2024，不能与会议年份混淆。
- [BGF-DR，Computers & Security 2026](https://www.sciencedirect.com/science/article/abs/pii/S0167404825004985) 的出版社可见内容已包含分支/状态反馈、双向变异、差分与指纹；本轮未取得全文，不能据开放摘要断言它缺少某种机制。

因此，不以“多解析器 + 状态 + 混合测试 + fingerprint”的组合本身作为创新。更值得验证的是：**单 producer 的成本/遗漏权衡、异构 harness 的比较偏差、状态差异与后续可见错误之间的确认能力**。这些也仍是研究假设，不是给现有集成重新命名就成立的贡献。

## 候选贡献与证据门槛

### 当前材料能支持到哪里

本轮只读核验摘要，详见 [research/experiment-gaps.md](research/experiment-gaps.md)：

- 存在真实 BIND9 producer 记录：master `run_time=3599` 秒、约 421 万次执行；95 个 queue 文件对应 87 个唯一内容。不能把已有工作概括成“从未真正运行”。
- 所查五个 secondary × 四变体长回放，每格只有 1 run，并消费同一 producer 队列；它们能说明回放情况，不能说明四种生成方法的因果增益。
- 专门的 RQ2 失败批次没有因文档修正而变成成功实验；其他矩阵存在成功 replay，故也不能说所有 replay 都失败。
- 五个历史 ready 矩阵合计 100 replay runs、400 样本执行；移除元数据后的 100 份快照均为同一组 4 个文件。原摘要与当前排除元数据后的规则不一致，属于需要版本化解释的历史契约差异，不自动意味着数据被篡改。
- 三项当前代码缺口会影响语义结论；已有 3 个纯 Python 回归通过，但缺少相同缓存、错误 Question/截断报文等关键反例。

因此现有产物可作历史探索、回归和案例候选池；不能未经重验证直接复制成论文主表。

## 研究问题与实验矩阵

保留已有 RQ 编号，避免与仓库表格混淆。方法收益和工程可移植性分别回答。

| RQ | 比较与控制变量 | 主指标 | 对应论点 |
| --- | --- | --- | --- |
| RQ1 输入模型 | DST1、query-only、随机 wire packet、legacy response-tail；记录逐样本源身份和转换；同种子来源、同时间资源；另设统一后置查询的公平对照 | 分母明确的 parse/递归路径/有效响应/状态观察率；被排除样本数量与原因 | C1 |
| RQ2 同源差分 | 同源 replay 与各 resolver 独立生成/测试；两者都是真实执行，不用历史 queue 复制冒充；统一 resolver 配置与外部响应环境 | 有效可比较样本比例、语义 replay 成功率、差异候选、人工分钟/确认案例；总成本与目标数扩展 | C2 |
| RQ3 hybrid 消融 | 当前生成对照为 `full_stack / afl_only / no_mutator`；已确认等价的 `no_cache_delta` 合并为分析兼容标签。无回流/无 gate 仍须另行实现并验证，不能按名称凑组 | 同构建覆盖增长、独立确认候选/时间、首次发现时间、SymCC 新候选与回流数、运行开销 | 辅助贡献 |
| RQ4 状态降噪 | 无过滤、已有启发式、状态 fingerprint；固定同一候选池和真值；独立标注，分歧单独裁决 | 误报比例、正例召回、被过滤集抽查、cluster 数、定位时间；不能只报告 cluster 减少 | C2/C3 |
| RQ5 泛化 | BIND9、Unbound、Deadwood、dnsmasq、SmartDNS、Knot Resolver；按递归/转发/缓存能力分层，不假定角色相同 | 构建/有效 replay、cache 可观测性、适配改动、失败分类和确认行为差异 | 外部有效性 |

### 基线选择

1. 内部基线优先复用当前 AFL-only、query-only、无 gate、无 fingerprint，不因接入成本低而回避最接近外部工作。
2. 最接近的 DNS 差分工具应优先进行同环境复现；其代码、许可证、输入模型或依赖不可用时，记录确切障碍并缩小比较结论，不能把缺测填成零。
3. AFLNet、StateAFL 等通用协议工具是否纳入性能比较，取决于相同 DNS 目标/角色是否可接入；不能将不同协议配置下的数字横向拼接。
4. 拟议变体名称和现有配置并非自动一一对应。正式矩阵前输出“开关 → 实际执行路径 → 可观测证据”的对照表。
5. 历史长预算配置含 `full_stack / afl_only / no_mutator / no_cache_delta` 四标签；第二批命令级回归确认 `no_cache_delta` 与 `full_stack` 生成行为等价，新的生成对照收敛为前三组。`afl_only` 仍保留 DST1 mutator 等能力，应称“无 SymCC 对照”，不能冒充未经增强的原生 AFL++。拟议的无回流/无 gate 组须依据实际路径另行确定。

## 统计与有效性

- **实验单位**：生成效果以一次从冻结初始语料启动的 producer run 为单位。一个 run 中的数百样本不是数百独立重复；同一 producer queue 在五个 resolver 上 replay 也不是五次独立生成。
- **独立性**：记录随机种子、命令、运行区间、退出状态、初始语料哈希、目标二进制及实际 producer 输出。不以目录名、时间戳或哈希不同证明独立；合法独立运行也可能生成相同内容。
- **预算**：同时报告墙钟时间、进程/线程数量和总 CPU 时间。Hybrid 使用额外 solver/helper 时，AFL-only 比较须有同总资源预算或把额外资源作为明确的实验变量。
- **重复**：pilot 只查链路；正式探索阶段至少 5 个独立 run，并根据波动增补，不能把 5 次当作统计充分性的保证。正式重复数和停止规则在看结果前冻结。
- **指标**：保留每 run 原始值、样本标准差与现有契约的 95% CI。偏斜分布可补中位数/IQR及预先选择的稳健区间；不得事后挑有利统计法。单 run 的样本标准差/CI 不可伪造成零。
- **比较**：配对只用于共享初始语料、种子安排与资源计划的合理设计；每配置仍须实际独立执行。预先指定主指标和比较组，必要时控制多重比较，并报告效应量而非只报 p 值。
- **失败**：有效性分析只纳入满足契约的样本，但主表同时披露全部尝试量、失败率、排除原因及缺失量，防止仅筛成功样本抬高结果。
- **时间指标**：没有发现的 run 按预算右删失，不删掉，也不捏造发现时间。
- **覆盖**：不同编译选项、插桩方式或 resolver 的覆盖数字不可直接相加；同目标、同 coverage build 统一回放后比较。
- **真值**：未经人工/规范/因果重放确认的 candidate 不计作 bug，更不计作安全漏洞。新漏洞数量不设为必须达到的结果。

## 最小 pilot 与正式运行的边界

### G0：先校正测量工具

先处理可能改变实验解释的代码和数据来源问题，跑对应回归。旧结果只保留为历史快照，不在修复后继续沿用其语义结论。

### G1：仅做链路验证

建议先用 BIND9 与 Unbound，固定约 10–20 个有明确预期的小样本（含阴性/错误路径），通过同源 replay 与状态验证。另以每个配置 2 次、每次 60 秒的独立 producer pilot 核验执行证据。

四配置 pilot 的 producer 墙钟预算总和为 `4 × 2 × 60 = 480 秒`，**不含**构建、solver 并发 CPU、replay、分析或超时清理。这只是拟议上限，实际资源和隔离条件须在运行前明确；本轮没有运行或授权后台启动。

### G2：正式实验分档推进

先冻结 1 小时档和独立重复，验证结果再决定 6/24 小时档。以单 BIND9 producer、4 配置、5 次重复为例：

- 1 小时档需要 20 producer-run 小时；
- 1/6/24 小时均独立运行时需要 `4 × 5 × (1+6+24) = 620` producer-run 小时；
- 若采用一次 24 小时运行的嵌套 checkpoint，则为 `4 × 5 × 24 = 480` producer-run 小时；1/6/24 小时点相关，不能宣称为三组独立实验。

上述均不是 CPU 小时或最终墙钟工期。总 CPU 成本还取决于每 run 的并发进程，replay 成本还取决于样本数、resolver 数和单样本耗时。单一 producer 的生成成本不应再乘 replay resolver 数；RQ2 独立生成基线则需另算。正式预算另行确认，不默认全部启动。

## 论文材料和案例

- 主表只消费通过当前语义检查、来源检查和完整性审计的新批次；审计只是必要条件。
- 每个数值保留到原始 run/sample 的映射，并能由统一入口重算；图表和叙述不得各自手改数字。
- 争取形成 2–5 个有代表性的完整案例，包含输入、受控上游、前后状态、日志、最小化样本、后续查询结果、规范/策略解释和 replay 命令；不足时如实报告，不制造案例。
- 阳性案例应证明错误数据在受控条件下被写入并影响后续查询；阴性案例至少包含等价表示、正常拒绝、非缓存回答和 harness 故障。
- 威胁模型须明确攻击者是受控权威端、在途参与者还是其他角色；harness 能注入响应不证明现实中的 off-path 投毒可行。随机端口、事务 ID、DNSSEC 和 bailiwick 等现实约束必须单独讨论。
- 公开材料应具备版本锁、补丁、构建步骤、输入来源/许可证、结果校验和、复算入口和脱敏说明。被 `.gitignore` 排除的历史实验目录不能充当干净 checkout 的复现方案。

## 投稿与止损条件

不先承诺 CCF 等级。先选与验证深度匹配的安全/软件测试/网络系统方向，再核验当年征稿范围与截止时间；本轮未核验具体 venue 的征稿日期。

- 如与最接近工作没有实质方法差异，停止包装“新框架”，先补足明确方法差异，或考虑更适合复现/经验研究的投稿类型。
- 如 SymCC 没有可靠增益，保留负结果，正文主线不依赖它。
- 如只剩 harness 伪差异，先修系统，不能以增加 resolver 或跑更久替代有效性。
- 如没有足够确认案例，可写工具与方法的有限评估，但不能声称发现未知投毒漏洞。
